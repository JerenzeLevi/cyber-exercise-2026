1. EXECUTIVE SUMMARY
During Phase 4 of Operation False Assurance (Interactive Control and Long-Lived External Sessions), network forensics and
authentication metadata were examined to uncover the underlying enterprise Active Directory domain infrastructure. Telemetry
gathered from Zeek NTLM protocol negotiation logs ( zeek.ntlm ) revealed direct internal authentication from compromised
workstation 10.11.28.101 to the primary Domain Controller at 10.11.28.2 ( WIN-FGG5B8C1BYF ). The authentication metadata
successfully exposed the fully qualified Active Directory domain name as mytallbeer.com (FQDN: WIN-
FGG5B8C1BYF.mytallbeer.com ). Identifying this domain infrastructure provides crucial attribution for credential staging,
Kerberos/NTLM authentication boundaries, and internal privilege escalation vectors.

Attack Reconstruction
In Phase 4, the adversary leveraged persistent access on internal workstation 10.11.28.101 to interact with internal network
resources and establish long-lived external control sessions. During internal reconnaissance and service enumeration, the host
performed NTLM authentication against the local Domain Controller at 10.11.28.2 over TCP port 139 (NetBIOS Session
Service). The cryptographic challenge and NTLMSSP metadata captured by Zeek revealed the Domain Controller's NetBIOS
hostname ( WIN-FGG5B8C1BYF ), the server DNS name ( WIN-FGG5B8C1BYF.mytallbeer.com ), and the canonical Active Directory
tree/domain name ( mytallbeer.com ). This authentication confirms that the host operates within the mytallbeer.com AD tree,
which the adversary can target for Kerberoasting, DCSync, or lateral delegation abuse.

5. CONTAINMENT, ERADICATION AND RECOVERY
Immediate Actions
Isolate host 10.11.28.101 from the corporate LAN to sever active interactive C2 sessions and prevent DC lateral
exploitation.
Review Active Directory Domain Controller ( 10.11.28.2 ) security event logs (Events 4624, 4625, 4776) for anomalous
authentication tickets and privilege escalation attempts.
Reset passwords for any user or service accounts that authenticated from 10.11.28.101 within the mytallbeer.com
domain.
Additional Recommendations
Active Directory / Domain Security: Restrict NTLM usage across the domain and enforce Kerberos with AES encryption.
Restrict SMB (ports 139/445) inbound to Domain Controllers strictly to managed management bastions.
Network: Block external interactive communication on non-standard ports (such as TCP 2222) at perimeter firewalls.
Endpoint: Perform forensic triage on 10.11.28.101 for memory-resident backdoors, interactive shells, and scheduled tasks.
Recovery: Ensure Domain Controller integrity before re-introducing sanitized systems to the mytallbeer.com domain.
6. CONCLUSION
In Phase 4, the adversary maintained active interactive control on host 10.11.28.101 and engaged with internal infrastructure.
Analysis of Zeek NTLM authentication metadata captured the complete domain hierarchy, conclusively identifying the enterprise
Active Directory domain as mytallbeer.com hosted on Domain Controller WIN-FGG5B8C1BYF ( 10.11.28.2 ). The submission 
CTK{mytallbeer.com} was validated as correct on the CyberEx assessment platform.
7. EVIDENCE LIMITATIONS
Specific domain user account names used in the NTLM challenge were masked or not explicitly populated in the single parsed
NTLM summary record.
Endpoint event logs from the Domain Controller are required to verify whether ticket-granting or privilege abuse occurred post-
authentication.
