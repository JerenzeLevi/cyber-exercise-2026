1. EXECUTIVE SUMMARY
During Phase 4 of Operation False Assurance (Interactive Control and Long-Lived External Sessions), network telemetry was
analyzed to determine the enterprise Active Directory Domain Controller targeted by compromised workstation 10.11.28.101 .
Investigation across Zeek NTLM authentication streams ( zeek.ntlm ) and DNS SRV resource records ( zeek.dns ) within PCAP
import 9159a1b68fa050d28393c1863352b9d1 identified internal IP address 10.11.28.2 operating as the primary Domain
Controller under the NetBIOS computer hostname WIN-FGG5B8C1BYF (FQDN: WIN-FGG5B8C1BYF.mytallbeer.com ). The server
handles all core domain infrastructure services including DNS (port 53), Kerberos (port 88), NTLM/NetBIOS (port 139), LDAP
(port 389), and SMB (port 445) for the mytallbeer.com forest.

Attack Reconstruction
Following established interactive C2 control over internal workstation 10.11.28.101 ( DESKTOP-CLIENT1 ), the adversary
engaged in internal reconnaissance to map domain assets. The compromised host initiated NTLM authentication challenges
against 10.11.28.2 over ports 139 and 445, receiving challenge-response metadata containing the server NetBIOS name WIN-
FGG5B8C1BYF and forest root mytallbeer.com . Subsequently, the client performed automated Active Directory Domain
Controller discovery via DNS SRV queries ( _ldap._tcp.pdc._msdcs.mytallbeer.com ), which authoritatively returned win-
fgg5b8c1byf.mytallbeer.com hosted at 10.11.28.2 .

5. CONTAINMENT, ERADICATION AND RECOVERY
Immediate Actions
Isolate compromised host 10.11.28.101 to sever the attacker's foothold into the internal network.
Review Windows Event Logs on Domain Controller 10.11.28.2 (Event IDs 4624, 4625, 4672, 4768, 4769) for unauthorized
logons from 10.11.28.101 .
Reset passwords and invalidate Kerberos tickets (KRBTGT) for all domain administrative accounts.
Additional Recommendations
Active Directory Hardening: Disable NTLMv1 and restrict NTLM authentication across internal subnets in favor of Kerberos
with AES encryption.
Network Segmentation: Implement firewall access control lists (ACLs) restricting workstation access to Domain Controller
management ports (139, 445, 389).
Monitoring: Configure alert rules for anomalous DNS SRV discovery queries (e.g., _msdcs lookups originating from
standard client endpoints).
Recovery: Perform integrity verification and baseline comparisons on Domain Controller system binaries and group policies.
6. CONCLUSION
During Phase 4, network analysis confirmed that internal workstation 10.11.28.101 targeted the enterprise Active Directory
Domain Controller at IPv4 address 10.11.28.2 with hostname WIN-FGG5B8C1BYF (domain: mytallbeer.com ). The flag 
CTK{10.11.28.2|WIN-FGG5B8C1BYF} was submitted and successfully conquered on the CyberEx assessment portal.
7. EVIDENCE LIMITATIONS
Domain Controller internal audit event logs were not provided in the PCAP capture.
Encrypted Kerberos and SMB payload details could not be decrypted without the domain private keys.
