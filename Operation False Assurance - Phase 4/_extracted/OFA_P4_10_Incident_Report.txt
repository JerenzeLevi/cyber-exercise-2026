1. EXECUTIVE SUMMARY 
10% - 100 Points 
Summarize the activity observed during this phase. State what happened, the affected system, the nature of the 
malicious activity, and the operational significance. 
On 2025-10-08, compromised workstation 10.11.28.101 was observed establishing repeated authenticated SMB 
sessions (TCP/445) to internal server 10.11.28.2, identified via Zeek smb_mapping.log as WIN-
FGG5B8C1BYF.mytallbeer.com - a Domain Controller for the mytallbeer.com Active Directory domain. 
Seven SMB (TCP/445) connections were confirmed between 10.11.28.101 and the Domain Controller, the first 
observed at 2025-10-08 09:12:36 UTC (an earlier related session on TCP/139 to the same host was logged at 
09:00:05 UTC). Six sessions mapped the IPC$ administrative pipe and one session mapped the SYSVOL share. 
The same host pair also exchanged a high volume of Active Directory protocol traffic in the surrounding window - 
DNS, LDAP/LDAP-search, Kerberos, and DCE-RPC (epmapper, netlogon, lsarpc, and 80 drsuapi calls including 
DRSBind/DRSCrackNames/DRSUnbind) - consistent with directory-service enumeration or replication-protocol 
activity originating from the workstation. 
No IDL_DRSGetNCChanges call (the operation used to pull replicated data/password hashes, e.g. DCSync) was 
found in the reviewed dce_rpc data, so a confirmed credential-dumping event is not established from this evidence 
alone. 
Operational significance: SMB/administrative-pipe access to a Domain Controller from a workstation, combined 
with directory-enumeration RPC activity, is consistent with the lateral-movement / interactive-control stage of this 
intrusion (Operation False Assurance Phase 4) and warrants immediate isolation of 10.11.28.101 and review of 
authentication logs on the DC.

Attack Reconstruction 
Describe how the activity developed during the phase, what the attacker accomplished, and how the available 
evidence supports the conclusion. 
The workstation's first recorded interaction with the Domain Controller in this window is an SMB/NetBIOS session 
on TCP/139 at 09:00:05 UTC, followed 7.5 minutes later by the first SMB session on the standard TCP/445 port 
(09:12:36 UTC) - the connection this finding is scored on. 
Over the following ~75 minutes, six more SMB/445 sessions occurred at roughly 15-minute intervals, each mapping 
the IPC$ administrative named-pipe share used for RPC-over-SMB (DCE-RPC endpoint access), with one session 
additionally mapping the SYSVOL DISK share. 
In the same window, LDAP/LDAP-search, Kerberos and DCE-RPC traffic (epmapper, netlogon, lsarpc, and 80 
drsuapi calls) was exchanged between the same two hosts, culminating in repeated DRSBind / DRSCrackNames / 
DRSUnbind sequences at 10:37:42 and 10:42:35 UTC. 
This pattern - authenticated SMB/IPC$ access paired with directory-replication-service (drsuapi) RPC calls - is 
consistent with AD reconnaissance/enumeration tooling (e.g. BloodHound-style collectors or similar) run from the 
compromised workstation against the DC, rather than routine end-user file access. 
No IDL_DRSGetNCChanges call was observed, so full replication/DCSync-style hash extraction is not confirmed; 
the available evidence supports confirmed lateral SMB access and AD enumeration against the Domain Controller.

5. CONTAINMENT, ERADICATION AND RECOVERY 
5% - 50 Points 
Provide recommendations based on the findings from this phase. 
Immediate Actions 
1. Isolate 10.11.28.101 from the network immediately and preserve a forensic image; treat the host as 
compromised given its direct SMB/AD-enumeration access to the Domain Controller. 
2. On the Domain Controller (10.11.28.2 / WIN-FGG5B8C1BYF.mytallbeer.com), review Security event logs 
(4624/4625/5140/5145) for the account(s) that established the IPC$/SYSVOL sessions and drsuapi calls, and 
confirm whether the source is an authorized administrator. 
3. Force a credential reset for any account confirmed to have authenticated from 10.11.28.101, and review 
Replicating Directory Changes / Replicating Directory Changes All permissions on the domain to reduce DCSync 
exposure. 
Additional Recommendations 
Network: 
Restrict SMB (TCP 139/445) and RPC (135, dynamic high ports) access to Domain Controllers to only approved 
administrative source hosts/jump servers; alert on IPC$/SYSVOL access from non-admin workstations. 
Endpoint: 
Deploy/verify EDR coverage on 10.11.28.101 and sweep the 10.11.28.0/24 segment for the same behavioral 
pattern (repeated IPC$ mapping + drsuapi calls) on other hosts. 
Accounts / Credentials: 
Reset credentials for any account used from 10.11.28.101 against the DC; audit and minimize membership of 
groups holding Replicating Directory Changes / Replicating Directory Changes All rights. 
Active Directory, if applicable: 
Enable/verify Advanced Audit Policy for Directory Service Access and Account Management on the DC; adopt 
tiered administration so standard workstations cannot query drsuapi directly. 
Recovery: 
Reimage 10.11.28.101 if compromise is confirmed; monitor the DC for renewed IPC$/drsuapi activity from the host 
post-remediation, and specifically alert on any subsequent IDL_DRSGetNCChanges call.
