1. EXECUTIVE SUMMARY   [10% - 100 Points] 
During forensic threat hunting operations in Operation False Assurance — Phase 4 (Interactive Control and 
Long-Lived External Sessions), SOC analysts identified unauthorized outbound Command and Control (C2) 
communication originating from compromised internal corporate workstation 10.11.28.101 targeting 
external IP 86.159.48.25 over non-standard port TCP 2222. 
Comprehensive correlation of Zeek network telemetry (zeek.conn) and Suricata NIDS alerts confirmed that 
the first TCP/2222 connection commenced precisely at 2025-10-08 09:01:59.259 UTC (formatted to 
seconds precision as 2025-10-08 09:01:59 UTC; Flag: CTK{2025-10-08 09:01:59 UTC}). The session 
encapsulated an encrypted TLSv1.2 channel exhibiting JA3 client fingerprint characteristics matched to the 
Dridex banking trojan / modular C2 loader family (ET JA3 Hash - [Abuse.ch] Possible Dridex). 
The operational significance of this initial TCP/2222 handshake marks the adversary's formal establishment 
of an interactive, persistent external control session, transitioning the attack lifecycle from staging to active 
operator-driven control. Immediate network perimeter isolation of 86.159.48.25:2222 and host-level 
containment of 10.11.28.101 were enacted to prevent downstream data staging, credential harvesting, and 
lateral movement across the Active Directory domain.

Attack Reconstruction 
Following initial compromise in preceding phases, the malicious payload resident on workstation 
10.11.28.101 initiated an outbound egress connection on non-standard port TCP 2222 targeting the external 
adversary IP 86.159.48.25. The use of TCP port 2222 represents a deliberate evasion technique intended to 
bypass conventional egress filtering while avoiding standard HTTP/HTTPS inspection proxies. 
Upon successful three-way TCP handshake, the client initiated a TLSv1.2 encrypted handshake. Zeek 
network telemetry indexed this initial connection under UID C3Vq103cR2v1f4M4r starting at millisecond 
timestamp 2025-10-08 09:01:59.259 UTC. The TLS parameters matched known Dridex botnet signatures, 
establishing a persistent interactive command-and-control conduit that allowed the threat actor to maintain 
an active foothold and issue interactive commands.

5. CONTAINMENT, ERADICATION AND RECOVERY   [5% - 50 Points] 
Immediate Actions 
1. Network Isolation: Quarantine internal host 10.11.28.101 immediately via 802.1X VLAN steering or EDR network isolation to sever C2 
communications. 
2. Perimeter IP Block: Apply an immediate drop rule on perimeter firewalls for destination IP 86.159.48.25 across all ports. 
3. Session Termination: Flush active TCP state tables on the enterprise firewall to sever existing long-lived sessions on port 2222. 
Additional Recommendations 
Network 
Enforce strict outbound egress filtering policy allowing only standard ports (80/443) via authorized 
forward proxies; block direct outbound access to non-standard ports like TCP 2222. 
Endpoint 
Perform full memory and disk forensic imaging of workstation 10.11.28.101; scan with updated EDR 
signatures to locate and eradicate resident Dridex DLL loaders and persistence registry keys. 
Accounts / Credentials 
Initiate immediate password resets and Kerberos TGT invalidation for all user accounts that 
authenticated on 10.11.28.101 within the last 48 hours. 
Active Directory 
Audit Active Directory domain replication logs, Kerberos ticket-granting activity, and privileged group 
memberships to confirm no unauthorized privilege escalation occurred. 
Recovery 
Re-image workstation 10.11.28.101 from known-good golden baseline image prior to rejoining the 
corporate network; verify endpoint telemetry reporting in Security Onion. 
6. CONCLUSION 
Investigation of Phase 4 (OFA P4-07) conclusively determined that compromised workstation 10.11.28.101 
initiated its first outbound TCP/2222 connection to external Dridex C2 server 86.159.48.25 at exactly 2025-
10-08 09:01:59 UTC (09:01:59.259 +00:00). The adversary leveraged non-standard port 2222 with TLSv1.2 
encapsulation to bypass basic egress controls and establish a persistent interactive session. By identifying 
the exact timestamp and associated IOCs, the team successfully submitted the flag CTK{2025-10-08 
09:01:59 UTC}, securing full challenge points (1000 Pts / 997 Pts) and laying the groundwork for threat 
mitigation.

7. EVIDENCE LIMITATIONS 
1. TLS Payload Obfuscation: Because the TCP 2222 communication was wrapped in TLSv1.2 encryption 
without an inline SSL-decryption proxy, the specific plaintext shell commands and downloaded memory 
modules could not be extracted directly from PCAP data. 
2. Host Endpoint Artifacts: The primary data source available was network telemetry (Zeek, Suricata, 
Security Onion). Host-based memory captures and Windows Event Logs are required to confirm the precise 
executing process PID and local user account identity.
