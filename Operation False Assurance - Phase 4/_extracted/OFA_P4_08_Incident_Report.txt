1. EXECUTIVE SUMMARY 
During deep-dive network telemetry analysis for Operation False Assurance — Phase 4 (Interactive Control and Long-Lived External
Sessions), SOC analysts investigated anomalous high-volume outbound network traffic on destination port TCP 443 originating from
compromised internal workstation 10.11.28.101 near the end of the packet capture window. 
Forensic querying in Security Onion Hunt aggregating port 443 traffic ( destination.port:443 ) revealed that external IP address
78.31.67.7 received sustained, high-throughput interactive streams between 10:24:35 UTC (18:24:35 +08:00) and 10:42:00 UTC
(18:42:00 +08:00). Suricata NIDS alerts confirmed that this traffic was not standard HTTPS web browsing, but an active reverse interactive
screen-sharing and control session mediated by W32.DarkVNC / BackConnect ( ET MALWARE W32.DarkVNC Variant Checkin , ET
MALWARE BackConnect CnC Activity ). 
The operational significance of this channel demonstrates that the adversary successfully upgraded their interactive foothold into a full GUI-
based remote administrative session via reverse VNC tunneling over port 443. This allowed real-time operator-driven exploration, live
screen streaming, and preparation for interactive data staging. Immediate network egress blocking and host isolation were enforced to
mitigate active adversary control.

ATTACK RECONSTRUCTION
Following the establishment of initial C2 beaconing on port 2222, the adversary deployed a secondary interactive remote access capability
to achieve direct graphical control over workstation 10.11.28.101 . The attacker launched a DarkVNC BackConnect reverse proxy agent
that connected outbound from high ephemeral client ports ( 50001 , 50010 , 50111 , 50128 ) to remote infrastructure 78.31.67.7:443 . 
By tunneling custom VNC protocol streams over destination port 443 (the standard HTTPS port), the adversary effectively evaded egress
firewall restrictions that permit outbound web traffic. NIDS signatures confirmed the VNC handshake command sequences ( Start VNC
M1 ). Because VNC continuously transmits compressed screen bitmaps and bidirectional input telemetry, this connection generated the
largest sustained byte volume recorded across all TCP/443 destinations near the end of the packet capture.

5. CONTAINMENT, ERADICATION AND RECOVERY 
Host Network Isolation: Sever internal host 10.11.28.101 immediately from the network to terminate active DarkVNC desktop
streaming.
Perimeter IP Block: Add an immediate firewall drop rule for external IP 78.31.67.7 across all ports.
State Table Flush: Terminate all active stateful sessions bound for port 443 on 78.31.67.7 .
6. CONCLUSION
Forensic analysis of Phase 4 (OFA P4-08) confirmed that external IP address 78.31.67.7 received the high-volume TCP/443 traffic near
the conclusion of the capture timeline (10:24:35 to 10:42:00 UTC). The adversary utilized W32.DarkVNC BackConnect reverse proxy
tunneling over standard HTTPS port 443 to achieve full graphical interactive desktop control. Submitting the flag CTK{78.31.67.7}
secured full points (1000 Pts / 997 Pts) and established critical intelligence for containment. 
7. EVIDENCE LIMITATIONS
1. VNC Frame Decryption: Because the VNC data stream was transmitted as compressed binary over port 443, live reconstructed video
playback of the operator's exact clicks and keystrokes requires dedicated DarkVNC session decoders.
2. Host Memory Context: Endpoint volatile memory capture is required to pinpoint the exact injected process ID (PID) hosting the VNC
DLL server.
